# 콘텐츠·데이터 구조

**문서 ID:** GDD-DAT-001 · **버전:** 1.1-review  
**관련 문서:** [증거·판정·엔딩](../20_systems/증거-판정-엔딩.md), [호출 작성 템플릿](../templates/call-template.md)

## 목표

기획자가 새 근무, 호출, 대사, 증거, 결과 문구를 데이터로 추가한다. 실행 코드는 콘텐츠의 순서와 표현을 공통 규칙으로 처리한다.

데이터만으로 새 콘텐츠를 늘릴 수 있는 것은 기존에 지원하는 입력·증거·판정·화면 요소의 조합 안에서다. 새 메커니즘은 런타임 구현이 먼저다.

## 콘텐츠 계층

**팩 → 노선/역 → 에피소드 → 근무 → 호출 → 증거·선택지·결과**

- **팩:** 배포/선택 가능한 콘텐츠 단위와 버전
- **노선/역:** 장소, 구역, 카메라 피드, 재사용 장면 템플릿
- **에피소드:** 하나의 이야기와 사건 묶음
- **근무:** 플레이 가능한 회차, 호출 순서, 판정 프로필
- **호출:** 발신자, 문제 제기, 선택지, 판정 및 결과 참조
- **증거:** CCTV, 운행 기록, 통화 로그, 근무 메모, 센서 등

## 데이터 경계

| 종류 | 예시 | 소유자 |
|---|---|---|
| 정적 콘텐츠 | 대사, 증거, 정답 기준, 선택 효과 | 콘텐츠 팩 |
| 정적 표현 | 장면 템플릿, 아이콘 ID, 효과음 ID, 번역 문구 | 장면/현지화 팩 |
| 공통 규칙 | 사건 진행, 판정기, 로그/점수 적용, 결말 선택 | 런타임 |
| 세션 상태 | 현재 사건, 본 자료, 선택 이력, 점수/잔향, 지속 장면 흔적 | 실행 중 세션 객체 |
| 장기 저장 | 완료한 에피소드, 사용자 설정 | 향후 저장 레이어. 첫 에피소드에서는 사용하지 않음 |

콘텐츠 원본 객체를 플레이 중 변경하지 않는다. 런타임은 별도 세션 상태를 만들고, 선택 효과를 그 상태에 적용한다.

## 콘텐츠 파일 구조 제안

    game-data/

      stations/

      scenes/

      packs/
        night-shift-01.js
        night-shift-02.js

팩 목록은 manifest에 선언한다. 새 에피소드는 packs 아래 새 데이터 파일로 작성하고 목록에 팩 ID를 추가한다. 수정이 필요한 것은 데이터 파일뿐이며, 기존 화면과 규칙을 사용하는 한 런타임 코드는 변경하지 않는다.

### 실행 호환 방식

현재 웹 프로토타입의 파일 직접 실행 방식을 고려해 초기 데이터 로더는 외부 패키지 없이 동작해야 한다. 정적 JSON을 fetch하는 방식은 웹 서버가 없는 file 실행에서 제약이 생길 수 있으므로, 첫 분리 단계에서는 일반 스크립트가 순수 데이터 객체를 등록하는 방식을 권장한다.

콘텐츠 파일에는 함수, DOM 조작, 임의 코드 실행을 넣지 않는다. 데이터 객체와 승인된 효과 ID만 허용한다. 다만 일반 스크립트 로드는 실행 자체를 막는 보안 경계가 아니므로 첫 단계는 프로젝트가 직접 관리하는 로컬 팩에만 적용한다. 외부 제작자의 팩을 허용할 때는 데이터 포맷과 로더의 보안 설계를 별도로 결정한다. 데이터 검증은 개발/빌드 단계에서 수행한다.

## 호출 데이터 계약

필수 필드:

- incidentId, schemaVersion
- timeLabel, titleKey
- caller.type, caller.displayKey, caller.messageKey
- primaryFeedId, evidenceIds (선택 전 공개하는 결정적 자료 두 개 이상)
- choices: choiceId, channel (`broadcast` / `withhold`), textKey, judgement/evaluationRef, recordTrustDelta, echoDelta, effectIds, feedbackKey, logKey
- 각 증거: evidenceId, sourceId, observedAt, displayedState, contentKey
- 선택 효과: 즉시 결과와 지속 장면/기록 상태를 구별하는 effectId 및 매개변수
- optional: flagsRequired. 부여·소비 플래그와 상태 해소 시각은 해당 효과 인스턴스에 선언

사건·선택지·증거 ID는 팩 안에서 고유하고 팩 ID와 함께 전역에서 식별 가능해야 한다. 사건이 요구하는 자료, 문구, 장면, 효과 ID가 실제 데이터에 존재해야 한다. 선택지 세 개의 판정은 정확히 하나만 기준에 맞아야 한다. 증거는 모두 응답 전에 접근 가능해야 하며, 호출자의 주장을 제외한 서로 다른 출처 두 개 이상이 정답의 이유를 뒷받침해야 한다.

`recordTrustDelta`와 `echoDelta`는 점수 변화의 유일한 출처다. 평가기가 선택 확정 때 한 번만 적용한다. `effectIds`는 점수와 로그를 제외한 장면·플래그·음향 효과만 참조하고, 선택 로그는 `logKey`로 자동 작성한다. 효과 ID는 등록된 효과 인스턴스를 가리키며 각 인스턴스는 아래 허용 타입 하나를 선언한다.

### 허용 효과 예시

| 허용 효과 타입 | 동작 |
|---|---|
| set_scene_state | 정의된 장면 구성요소의 상태 변경. 지속 여부와 해소 전환을 명시 |
| grant_flag / consume_flag | 후속 사건의 조건 상태 부여/소비 |
| play_feedback | 등록된 피드백 음향/시각 효과 실행 |

새 효과 타입을 추가할 때는 런타임을 확장한다. 기존 타입을 쓰는 효과 인스턴스·값이나 문구 변경은 데이터만 수정한다.

## 데이터 예시

다음은 필드 관계를 설명하기 위한 의사 데이터다. 필드명은 런타임 스키마 승인 후 고정한다. 문구와 증거 본문은 별도 키/ID로 연결한다.

    {
      "incidentId": "CALL-01-001",
      "schemaVersion": 1,
      "timeLabel": "00:17",
      "titleKey": "call.exit02.title",
      "caller": {
        "type": "station_phone",
        "displayKey": "call.exit02.source",
        "messageKey": "call.exit02.message"
      },
      "primaryFeedId": "FEED-EXIT-02",
      "evidenceIds": ["EVID-001-A", "EVID-001-B"],
      "choices": [
        {
          "choiceId": "CH-001-CLOSED",
          "channel": "broadcast",
          "textKey": "choice.exit02.closed",
          "judgement": "matched",
          "recordTrustDelta": 1,
          "echoDelta": 0,
          "effectIds": ["FX-EXIT-LOCK-STABLE"],
          "feedbackKey": "feedback.exit02.closed",
          "logKey": "log.exit02.closed"
        }
      ]
    }

실제 사건 데이터에는 나머지 선택지 두 개와 각 효과 인스턴스의 타입·지속/해소 조건도 들어간다. 예시 배열 한 개만으로는 유효한 사건 데이터가 아니다.

## 장면 표현 데이터

새 사건은 기존 장면 템플릿을 우선 재사용한다. 새 구역은 승인된 재사용 요소(문, 표지판, 바닥선, 조명, 인물 실루엣)를 장면 좌표에 배치하는 데이터로 정의한다.

임의 SVG/HTML 문자열을 사건 데이터에 넣지 않는다. 구조화된 장면 데이터만 허용해 검증, 접근성, 화면 크기 대응을 보장한다. 새로운 장면 요소 타입은 공통 렌더러에 추가해야 한다.

## 작성·검증 절차

1. 고유 팩/에피소드/근무/호출 ID를 발급한다.
2. 근무 순서와 사건 연결을 정한다.
3. 호출마다 자료, 선택지, 판정, 결과를 참조 ID로 연결한다.
4. 문구 키, 피드, 장면 상태, 효과 ID가 모두 등록됐는지 검사한다.
5. 선택지마다 판정이 하나로 결정되고 근무 결말 조건이 전체 점수·잔향 범위를 빠짐없이 처리하는지 검사한다.
6. 효과가 자료를 덮어쓰거나 후속 호출의 결정적 근거를 무효화하지 않는지 검사한다. 일시 효과에는 해소 전환과 남는 흔적을 요구한다.
7. 첫 근무의 3⁵=243개 선택 경로를 자동 검증해 중복 적용, 점수 상한, 결말 유일성, 필수 자료 접근, 장면 상태 모순을 확인한다.
8. 팩을 선택해 플레이하며 자료 대조와 결과 피드백을 확인한다.

콘텐츠 작성 단위와 질문은 [호출 작성 템플릿](../templates/call-template.md)을 따른다.
