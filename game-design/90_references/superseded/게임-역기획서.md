# 《다음 역은 없습니다》 게임 역기획서

**문서 버전:** 0.1  
**작성 기준:** 현재 바닐라 웹 프로토타입  
**목적:** 구현된 화면과 규칙을 바탕으로 게임의 경험, 시스템, 콘텐츠를 역으로 정리한다.

> 보관본입니다. 현재 목표 규칙은 [정본 GDD 목차](../../README.md)와 00–50 문서를 따릅니다.

> 이 문서는 구현에서 직접 확인되는 내용과 기획 의도에 대한 해석을 구분한다. 코드에 없는 세계관이나 규칙은 확정 사실로 다루지 않는다.

## 1. 게임 개요

| 항목 | 내용 |
|---|---|
| 제목 | 다음 역은 없습니다 |
| 장르 | 심리 공포 · 관찰/판단형 어드벤처 |
| 플레이어 역할 | 막차 이후 역에 홀로 남은 야간 관제원 |
| 플랫폼 | 설치 없는 데스크톱·모바일 웹 |
| 한 회차 | 고정된 호출 5건으로 진행하는 짧은 근무 |
| 핵심 행위 | CCTV·운행표·통화 기록을 대조하고, 안내 방송 또는 침묵을 선택한다 |
| 핵심 약속 | 방송 문장은 단순한 설명이 아니라 역의 상태에 영향을 준다 |
| 전투·이동 | 없음. 플레이어는 관제실을 떠나지 않는다 |

### 한 문장 소개

마지막 열차가 떠난 뒤, 서로 맞지 않는 호출과 기록을 확인하고 어떤 문장을 역에 방송할지 판단하는 관제실 심리 공포 게임이다.

**기획 해석:** 플레이어가 괴물을 직접 상대하는 대신 정보의 신뢰성을 판단하게 함으로써 “무엇을 말해야 하는가”를 공포의 중심에 둔다. 마이크는 상황을 통제하는 도구이자 이상현상을 현실로 불러올 수 있는 위험이다.

## 2. 경험 목표와 설계 원칙

### 플레이어 경험의 흐름

1. 평범한 관제 업무를 수행하며 공간과 기록의 정상 상태를 익힌다.
2. 호출자의 요구와 CCTV·시간표가 어긋날 때, 먼저 확인하고 싶은 불안을 느낀다.
3. 방송을 선택한 뒤에는 말한 내용이 현장에 반영됐는지 확인한다.
4. 잘못된 판단이 쌓일수록 관제실도 안전한 장소인지 의심한다.
5. 마지막 방송과 근무 기록을 통해 자신의 선택을 되짚는다.

### 설계 원칙

- **확인 후 응답:** 전화만 믿지 않고 서로 다른 정보원을 대조하도록 한다.
- **말의 결과:** 문구 선택을 현장 변화와 연결한다.
- **일상 업무의 침식:** 시간표, 호출, 기록처럼 익숙한 업무 자료에 이상을 끼워 넣는다.
- **무력감 대신 판단:** 이동·전투보다 관찰과 응답 책임을 중심에 둔다.
- **짧고 명료한 회차:** 다섯 건의 호출을 하나의 야간 근무와 결말로 묶는다.

## 3. 핵심 플레이 루프

1. 호출을 받는다.
2. CCTV를 확인한다.
3. 운행표와 통화 기록을 대조한다.
4. 안내 방송 문구 또는 침묵을 선택한다.
5. 현장 피드백과 근무 기록을 확인한다.
6. 다음 호출로 넘어가며, 다섯 번째 응답 뒤 근무 결말을 확인한다.

정보 화면을 열거나 카메라를 바꾸는 데 시간·전력·자원을 쓰지 않는다. 현재 구현은 정답을 고르는 퍼즐에 가깝고, 조사 순서에 따른 별도 비용은 없다.

### 조작

- 선택지를 클릭하거나 숫자 1–3 키로 선택한다.
- Enter 키로 근무를 시작하고, 응답 후 다음 호출로 넘어간다.
- CCTV 카메라, 운행표, 통화 기록 화면은 언제든 전환할 수 있다.
- 근무 종료 화면에서 Enter를 누르거나 재시작 버튼을 선택하면 같은 근무를 다시 시작한다.

## 4. 정보 도구와 화면

| 도구 | 현재 프로토타입 동작 | 플레이 목적 |
|---|---|---|
| CCTV | 출구, 승강장, 역무실 복도 3개 화면 전환 | 눈에 보이는 현장 상태와 호출 내용을 비교한다 |
| 운행표 | 현재 호출에 연결된 시간표/시설 기록과 현장 메모 표시 | 운행 여부, 시설 상태, 근무 정보를 확인한다 |
| 통화 기록 | 현재 호출과 이전 호출의 대화를 시간순으로 표시 | 호출자의 주장과 반복되는 표현을 다시 살핀다 |
| 방송 선택 | 호출마다 고정 문구 2개와 침묵/보류 1개 제공 | 사실을 전달하거나, 위험한 말을 하거나, 응답을 보류한다 |
| 근무 지표 | 기록 신뢰도, 방송실 잔향, 호출 진행 표시 | 누적 결과와 진행 상황을 확인한다 |
| 음향 버튼 | 기본 꺼짐. 켜면 낮은 지속음과 선택 피드백음 재생 | 관제실의 정적과 응답 순간을 보강한다 |

### 화면 구성

- **왼쪽:** 현장 정보 단말, CCTV/운행표/통화 기록 탭
- **오른쪽:** 호출 내용, 안내 방송 선택지, 근무 지표
- **시작 화면:** 근무 배경과 “확인한 사실만 말한다”는 기본 수칙
- **종료 화면:** 근무 판정, 기록 신뢰도, 잔향 수치, 다섯 선택의 요약

## 5. 근무 콘텐츠

호출은 정해진 순서로 나오며, 시각은 실제 시간 제한이 아니라 장면의 진행 표식이다.

| 순서·시각 | 호출 | 확인 단서 | 기록상 판정 응답 | 즉각적인 결과 |
|---|---|---|---|---|
| 1 · 00:17 | 닫힌 출구 | 호출은 2번 출구가 열렸다고 주장하지만 시간표는 공사 폐쇄, C01은 셔터 잠금을 보여 준다 | “2번 출구는 폐쇄되었습니다.” | 잠금등이 켜지고 통화선의 숨소리가 멎는다 |
| 2 · 00:26 | 없는 열차 | 호출은 열차 도착 방송을 요구하지만 운행은 취소됐고 C02 선로는 비어 있다 | “3번 승강장에는 운행 열차가 없습니다.” | 취소 안내가 반복되고 진동이 멀어진다 |
| 3 · 00:35 | 노란 선 너머 | C02에 인물이 노란 선 가까이 서 있다. 열차 진입 기록은 없다 | “노란 선 뒤로 물러나 주십시오.” | 인물이 물러나고 형광등이 안정된다 |
| 4 · 00:44 | 퇴직자의 내선 | 사용 중지된 101 내선에서 연락이 왔으며, 영상은 빈 복도, 근무표는 1인 근무다 | 아무 말 없이 내선을 끊고 기록한다 | 통화는 끊기지만 수화기 안쪽에서 숨소리가 난다 |
| 5 · 00:58 | 마지막 안내 | 운행은 끝났고 다음 역 정보가 비어 있다. 발신은 전화가 아니라 방송실 마이크에서 들린다 | “다음 역은 없습니다.” | 안내등이 꺼지고 화면에 제목 문구가 남는다 |

### 호출별 공포 장치

- **1번:** 확인 가능한 폐쇄 기록과 “열려 있다”는 요청이 충돌한다.
- **2번:** 취소된 열차의 도착을 안내해 달라는 요구가 역의 현상을 유도한다.
- **3번:** 승객 안전을 위한 안내와 이상한 인물의 반응이 연결된다.
- **4번:** 발신 기록이 없는 옛 내선과 1인 근무 정보가 신원에 대한 의심을 만든다.
- **5번:** 외부 호출에 응답하던 플레이어가 자신의 마이크에서 나온 호출을 판단한다.

**기획 해석:** 앞의 호출은 기록에 맞춰 사실을 알리는 업무 규칙을 익히게 하고, 네 번째는 침묵도 유효한 판단임을 강조한다. 마지막은 그 규칙을 플레이어 자신에게 되돌린다.

## 6. 규칙과 진행 시스템

### 선택과 기록

- 호출마다 한 번만 선택할 수 있다.
- 호출 데이터에 지정된 판정 응답이면 기록 신뢰도가 1 증가한다.
- 다른 응답이면 방송실 잔향이 1 증가한다. 잔향은 화면상 최대 4까지 표시된다.
- 선택 결과와 문구는 근무 로그에 저장된다.
- 오답은 현재 호출에 맞는 문장 및 일부 시각 피드백을 제공한다. 다음 호출의 정답·단서·행동 조건은 바꾸지 않는다.

### 결말 판정

| 기록 신뢰도 | 판정 | 결말 방향 |
|---:|---|---|
| 5/5 | 정상 | 퇴근 처리는 끝나지만, 역 이름 대신 플레이어의 근무 번호가 안내판에 나타난다 |
| 3–4/5 | 보류 | 대부분의 기록은 확인됐으나 누군가 플레이어의 목소리로 다음 근무자를 부른다 |
| 0–2/5 | 미귀가 | 시스템에는 근무자 1명과 입실 기록만 남아 퇴근 여부가 불분명하다 |

결말은 누적 정답 수로 결정된다. 마지막 문구 선택 자체에 독립된 분기 조건은 없다. 같은 근무를 다시 시작할 수 있지만 현재는 순서와 내용이 고정되어 있다.

### 게임 상태

시작 화면 → 근무 중(호출 1–5) → 응답 결과 확인 → 근무 결말 → 재시작

실패로 조기 종료되는 상태, 생명/체력, 이동, 전투, 인벤토리, 저장 데이터는 없다.

## 7. 시각·음향 방향

- 저채도 녹색과 청록색, 제한된 황색 경고, 잔향/위험 표시용 붉은색을 사용한다.
- 관제실은 어두운 작업 단말처럼 구성하고, CCTV에는 스캔라인과 비네팅을 얹는다.
- 출구·승강장·역무실 복도를 단순화한 SVG 장면으로 그린다. 외부 이미지나 영상은 사용하지 않는다.
- 인물 실루엣, 터널 조명, 잠금등, 빈 목적지 표지판 등 적은 요소를 변화시켜 이상을 드러낸다.
- 음향은 사용자가 켠 경우에만 재생한다. 지속 저음은 배경, 높거나 낮은 단음은 선택 피드백에 대응한다.
- 점프 스케어보다 정적인 화면, 이상한 통화, 말 뒤의 변화를 우선한다.

## 8. 범위와 실행 구조

### 포함 범위

- 한 장소, 한 근무자, 다섯 개의 고정 호출
- 세 개의 고정 CCTV 피드 및 호출별 운행 기록
- 호출별 선택지와 즉각적인 결과 피드백
- 정답 수에 따른 세 가지 근무 판정
- 반응형 HTML/CSS/JavaScript, 브라우저 내 SVG 장면과 Web Audio 효과
- 로컬 HTML 파일로 실행하며 외부 패키지나 서버에 의존하지 않음

### 현재 범위 밖

- 자유 입력 음성 인식, 직접 작성하는 방송 문장
- 실시간 열차 운행 시뮬레이션, 시간 제한, 감시 공백 관리
- 플레이어 이동, 추격, 은신, 전투
- 절차적 사건 생성, 다음 근무로 이어지는 캠페인, 세이브/기록 저장
- 여러 지역·캐릭터·난이도·엔딩 장면

## 9. 역기획에서 확인한 미정 사항과 개선 후보

아래는 현재 구현과 플레이 약속 사이에서 확인한 후속 설계 과제다. 수정 사항이 아니라 검토 항목이다.

1. **관찰 비용이 없다.** 플레이어는 세 자료를 언제든 무료로 확인할 수 있어 망설임의 원인은 선택 문구에 집중된다. 더 긴 버전에서도 정보를 무제한 제공할지, 확인하는 동안 다른 카메라를 놓치는 구조를 더할지 결정이 필요하다.
2. **정답 판정이 색으로 즉시 드러난다.** 선택 직후 올바른 응답은 녹색 계열, 다른 응답은 붉은 계열 피드백을 받는다. 불확실성을 오래 유지하려는 방향이라면 판정을 언제 공개할지 검토할 수 있다.
3. **누적 수치가 서로 겹친다.** 잔향은 오답 수, 기록 신뢰도는 정답 수를 센다. 다섯 번 선택만 있는 현재 구조에서는 사실상 반대 지표다. 잔향을 이후 호출/영상에 반영하거나 두 지표 중 하나를 줄일 수 있다.
4. **현장 동기화 표시가 판정과 일치하지 않는다.** 응답 뒤에는 정답 여부와 관계없이 “불안정”으로 표시된다. 이 라벨이 누적 판정인지 단순 응답 처리 상태인지 정의가 필요하다.
5. **장면 반응의 강도가 호출마다 다르다.** 1·2·4번 일부 선택은 결과 문구에 주로 의존하고, 3·5번은 CCTV 상태도 달라진다. 모든 선택에서 기대하는 시각 피드백 수준을 정하면 일관성이 높아진다.
6. **근무 판정과 마지막 선택이 분리되어 있다.** 5번째 응답은 제목 문구를 완성하는 핵심 장면이지만, 엔딩 종류는 앞선 선택을 포함한 총점으로만 결정된다. 마지막 문장의 의미를 결말 분기와 연결할지 결정할 수 있다.
7. **정답이 반복 플레이에서도 고정되어 있다.** 한 번의 플레이로 정보 배치를 학습하면 재플레이 판단이 쉬워진다. 기록 불일치 조합이나 사건 순서를 변주할지는 반복성 목표에 따라 판단한다.
