# 《다음 역은 없습니다》 수용 기준

**문서 ID:** GDD-ACC-001 · **작성일:** 2026-09-28  
**기준:** `game-design` 정본 문서 버전 1.1-review

## 목적과 판정 범위

이 문서는 **첫 번째 근무 `PACK-NIGHT-01 / EP-01 / SHIFT-01`의 데이터 기반 웹 구현**을 인수할 때 확인할 기준이다. 현재 프로토타입이 이 기준을 충족했다는 뜻은 아니다. 규칙이나 사건 내용이 충돌하면 [증거·판정·엔딩](20_systems/증거-판정-엔딩.md)과 [에피소드 01](30_content/episode-01.md)을 우선한다. 이 문서는 두 정본의 규칙을 검사 항목으로 옮긴다.

- **필수 수용 범위:** 아래 AC-01~AC-31. 각 항목에 자동 검사 결과나 수동 플레이 기록을 남기고 모두 통과해야 한다.
- **별도 관찰 검증:** AC-32~AC-34는 플레이어 경험을 확인하는 [로드맵 4단계](50_production/roadmap.md#4단계--확장-에피소드-제작)의 기준이다. 첫 근무의 기능 수용 결과와 구분해 기록한다.
- **범위 밖:** 자유 이동, 전투, 음성 인식, 시간 제한, 온라인/계정/클라우드 저장, 외부 제작자 팩 실행. P1 VFX 시트와 P2 장식은 첫 근무의 필수 완료 조건이 아니다.

## 4. 판정·결말·로그

| ID | 수용 기준 | 확인 방법 |
|---|---|---|
| AC-13 | `recordTrust`와 `echo`는 0에서 시작한다. 선택 확정 시 판정 → 변화량·흔적 적용 → 결과 표시 → 다음 호출 활성화 순으로 한 번만 처리한다. 신뢰도는 기준에 맞는 선택당 +1, 범위 0–5다. 잔향은 선택별 +0~+2를 더해 표시·판정값을 4로 제한한다. | 경계값·중복 입력 자동 검사 |
| AC-14 | 결말은 `recordTrust ≤ 2` **또는** `echo ≥ 4`면 **미귀가**, 아니고 `recordTrust = 5` **그리고** `echo ≤ 1`이면 **정상**, 나머지는 **보류**로 위 순서에 따라 한 번만 결정한다. | 모든 신뢰도 0–5 × 잔향 0–4 조합 검사 |
| AC-15 | 첫 근무 3⁵ = **243개** 선택 경로가 모두 결말 하나로 끝난다. 현행 선택값 기준 분포는 **정상 1, 보류 28, 미귀가 214**다. 모든 기준 선택 경로는 신뢰도 5·잔향 1·정상이며, 잔향 4 이상은 신뢰도가 높아도 미귀가다. | 전 경로 자동 열거 및 기대값 비교 |
| AC-16 | 조사·응답 직후에는 호출 진행과 발생 현상만 보인다. 정오, 신뢰도·잔향 수치, 빨강/초록 판정 색이나 정오를 알리는 확인·오류음을 공개하지 않는다. | 각 화면 단계의 HUD·색·음향 확인 |
| AC-17 | 종료 화면은 결말, 신뢰도, 잔향, 호출별 선택·기준 일치 여부와 **선택 당시에 볼 수 있던 근거**를 보여 준다. 로그에는 호출·선택지 ID, 서사 시각, 근무 순서, 판정, 실제 적용 점수, 결과가 남고 벽시계 시각을 생성하지 않는다. 잔향 상한에 닿아도 선택의 원래 `echoDelta`를 보존한다. | 종료 로그와 기대 세션 기록 대조 |

## 5. 콘텐츠 분리와 검증

| ID | 수용 기준 | 확인 방법 |
|---|---|---|
| AC-18 | 다섯 호출의 문구·증거·선택·판정·효과는 콘텐츠 팩에서 로드한다. 호출 순서나 텍스트를 바꾸고 기존 타입의 새 사건을 추가할 때 사건별 런타임 `if/switch`를 고치지 않는다. | 데이터 수정 후 동일 런타임 실행·코드 검토 |
| AC-19 | 팩 → 역 → 에피소드 → 근무 → 호출의 참조와 manifest 연결이 유효하다. 사건·선택지·증거 ID는 팩 안에서 고유하고 팩 ID와 함께 전역 식별 가능하다. 각 호출은 선택지 세 개와 기준에 맞는 선택지 정확히 하나를 가진다. | 개발/빌드 단계 콘텐츠 검증 |
| AC-20 | 모든 필수 필드, 증거·문구·피드·장면·에셋·효과 참조와 선택 언어의 번역 키가 존재한다. 알 수 없는 타입·참조·중복 ID·번역 누락은 근무 시작 전에 필드와 원인을 확인할 수 있게 실패한다. | 결함을 넣은 팩의 검증 오류 확인 |
| AC-21 | `recordTrustDelta`와 `echoDelta`만 점수를 바꾼다. `effectIds`는 등록된 장면 상태, 플래그, 피드백 효과만 사용하고 로그는 선택의 `logKey`로 자동 작성한다. 콘텐츠 객체는 플레이 중 변경되지 않는다. | 팩 스키마·세션 상태·재시작 검사 |
| AC-22 | 사건 데이터는 임의 SVG/HTML 문자열, 함수, DOM 조작이나 사건별 코드를 포함하지 않는다. 승인된 구조화 장면 요소와 효과 타입으로 표현한다. 새 타입은 런타임·검증 규칙 추가 후 사용한다. | 스키마 검사 및 데이터 리뷰 |
| AC-23 | 첫 근무 243개 경로에서 점수 상한, 중복 적용 방지, 결말 유일성, 결정적 자료 접근, 지속·일시 장면 상태와 후속 호출의 근거 보존을 자동 검사한다. | 경로 검증 보고서 |

## 6. 화면·음향·접근성·아트

| ID | 수용 기준 | 확인 방법 |
|---|---|---|
| AC-24 | 자료와 선택지가 같은 화면 흐름에서 확인 가능하고, 호출·응답은 자료 아래에 묻히지 않는다. 각 선택지의 `방송`/`방송 보류` 채널 표시가 동등하게 보인다. 조사·결과 화면의 근무 지표는 호출 진행만 사용한다. | 데스크톱·모바일 화면 검토 |
| AC-25 | CCTV 단서의 시각·출처·문구가 스캔라인, 비네팅, 효과에 가려지지 않는다. 시설·위험 색은 정오 판정과 구별되고, 색 외에 텍스트·형태로도 상태를 알 수 있다. | 주요 장면 가독성·색 구분 확인 |
| AC-26 | 음향은 기본 꺼짐이다. 켜거나 꺼도 정보·결과를 동일하게 이해할 수 있다. 방송 보류는 역내 방송음을 내지 않고, 정답/오답을 알려 주는 고저음 패턴을 사용하지 않는다. | 무음 전 회차와 음향 켠 회차 비교 |
| AC-27 | 모든 버튼에 보이는 키보드 포커스가 있다. 호출·결과·결말 점수와 CCTV 핵심 단서·이전 흔적은 보조 기술이 읽을 수 있는 텍스트/캡션으로 제공한다. 호출 전환 시 새 제목을 안내한다. | 키보드와 보조 기술로 시작~재시작 수동 확인 |
| AC-28 | 320px 너비에서 문구가 잘려 숨지 않고 스크롤 또는 세로 배치로 접근 가능하다. 움직임 줄이기 설정에서 화면 애니메이션을 끄거나 정지 대체를 제공한다. | 320px 뷰포트·동작 줄이기 설정 확인 |
| AC-29 | 첫 근무에 필요한 P0 장면은 세 CCTV 배경과 셔터·문·표지·조명·인물·흔적 상태를 표현한다. 공통 720×405 장면 좌표에서 사건별 변경 요소를 독립 상태로 교체할 수 있다. 핵심 단서는 VFX 없이도 보인다. | 세 구역·15개 결과의 화면/캡션 대조 |
| AC-30 | 장면 이미지에는 한글 정보 문구와 카메라 HUD를 굽지 않고 UI/콘텐츠 데이터로 표시한다. 에셋은 `assetId`를 통해 연결하고 상태별 파일 경로를 사건 데이터에서 조립하지 않는다. | 에셋 및 콘텐츠 참조 검토 |
| AC-31 | P1 VFX 시트를 제작해 포함할 경우 8×6 그리드, 128×128 프레임, 1024×768 투명 PNG와 대응 메타데이터를 따른다. 효과가 단서를 가리지 않고 움직임 줄이기 대체가 작동한다. VFX가 없어도 AC-12·AC-29를 통과한다. | 제작 시 아틀라스·메타데이터 대조 |

## 7. 플레이어 관찰 검증 · 별도 기록

| ID | 관찰 기준 | 기록 방법 |
|---|---|---|
| AC-32 | 대상 플레이어 **5명 이상**으로 첫 근무를 관찰한다. 최소 **4명**이 두 번째 호출까지 독립 자료 두 개를 열어 본다. | 익명 참가자별 자료 열람 기록 |
| AC-33 | 최소 **4명**이 자신의 선택으로 바뀐 화면 또는 기록 한 가지를 설명할 수 있다. | 선택 직후 설명과 실제 변화 대조 |
| AC-34 | 마지막 회고에서 네 번째 호출의 방송 보류와 세 번째 호출의 방송 보류가 부적절한 이유를 구분하는지 기록한다. 첫 플레이 결말 분포도 남긴다. 미달 또는 결말 쏠림은 놓친 단서와 잔향값을 검토해 수정한 뒤 재확인한다. | 회고 메모·결말 집계·수정 이력 |

AC-34의 구분 답변에는 정본이 인원별 합격 수를 정하지 않았다. 관찰 결과를 수치로 남기되 임의의 통과율을 추가하지 않는다.

## 수용 기록 양식

각 항목은 `통과 / 실패 / 미검증`으로 기록한다. `미검증`은 통과로 취급하지 않는다.

| 항목 ID | 결과 | 빌드/팩 버전 | 증거 링크 또는 재현 단계 | 확인자·날짜 |
|---|---|---|---|---|
| AC-__ | 미검증 | | | |

기능 수용에는 전 경로 자동 검사 결과, 15개 선택 결과 확인 기록, 키보드·보조 기술 수동 확인 기록을 첨부한다. 관찰 검증은 참가자 개인 정보를 제외한 집계와 수정 이력으로 남긴다.
