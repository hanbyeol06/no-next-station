# 제작 로드맵과 완료 기준

**문서 ID:** GDD-PRD-001 · **버전:** 1.1-review  
**목적:** 현재 단일 페이지 시제품을 데이터 추가형 콘텐츠 구조로 확장한다.

## 제안 프로젝트 구조

다음은 구현을 분리할 때의 소스 구조다. 지금 이 문서 작업에서 런타임 코드를 옮기거나 데이터 파일을 만드는 것은 아니다.

런타임은 게임 규칙과 화면 동작을 소유한다. game-data는 실행할 호출과 표현 ID를 소유한다. 콘텐츠가 사용할 수 있는 효과와 화면 요소는 데이터 스키마의 허용 목록으로 제한한다.

## 단계

### 0단계 · 문서 기준선 확정

- 비전, 핵심 루프, 판정, 콘텐츠 필드의 책임을 각 문서에 고정한다.
- 용어를 통일한다: 호출, 증거, 기록 신뢰도, 방송실 잔향, 근무.
- 결정 사항: 첫 근무의 신뢰도와 잔향은 선택별로 다른 값을 가지며 둘 다 결말에 영향을 준다. 응답 직후에는 현상만 보여 주고, 정오와 수치는 종료 화면에서 공개한다.
- 완료 기준: [15개 선택지](../30_content/episode-01.md)의 채널·판정·점수·결과가 시스템 규칙 및 UI와 일치한다.

### 1단계 · 현재 프로토타입의 데이터 분리

- 다섯 사건의 정적 데이터와 문자열을 game.js에서 콘텐츠 팩으로 옮긴다.
- 선택지 배열 번호 대신 안정된 ID로 판정한다.
- 선택별 채널과 효과를 데이터에 명시하고, 프로토타입의 오답 공통 장면 분기를 제거한다.
- 호출을 넘겨도 장면 흔적이 유지되게 한다. 두 번째 호출의 열차 불빛은 정해진 시각에 해소하고 흔적을 남긴다.
- 완료 기준: 15개 선택지마다 설계된 결과가 나오며, 사건 텍스트나 순서를 바꿔도 엔진의 사건별 분기 수정이 필요 없다.

### 2단계 · 범용 장면/효과/결말 로더

- SVG 장면을 승인된 요소와 상태 데이터 조합으로 표현한다.
- 점수, 잔향, 플래그, 로그, 지속/일시 장면 효과를 공통 평가기가 처리한다.
- 엔딩 임계값과 문구를 근무 프로필 데이터로 옮긴다.
- 신뢰도·잔향의 실시간 판정 표시를 제거하고 종료 로그에 당시 근거를 제공한다. 근무 수칙 카드를 시작 화면과 자료 화면에 추가한다.
- 완료 기준: 새 사건의 ID를 코드의 if/switch 조건에 추가하지 않고, 선택 결과가 후속 호출의 정답 자료를 덮어쓰지 않는다.

### 3단계 · 작성 검증 도구와 템플릿

- ID 중복, 참조 누락, 알 수 없는 증거/효과 타입, 번역 누락을 찾아낸다.
- 점수 전체 범위에 결말이 정확히 하나씩 배정되는지 검증한다.
- 첫 근무의 243개 선택 경로에서 점수 상한, 지속 상태, 결말 유일성, 자료 접근을 자동 확인한다.
- 호출 작성 템플릿으로 새 콘텐츠를 작성할 수 있게 한다.
- 완료 기준: 오류가 있는 팩은 근무 시작 전에 원인과 필드를 확인할 수 있다.

### 4단계 · 확장 에피소드 제작

- 기존 역·카메라·효과를 조합하는 호출을 새 팩으로 추가한다.
- 첫 에피소드와 정보 유형·침묵의 이유·현장 반응이 겹치지 않는지 검토한다.
- 플레이어 관찰 세션으로 자료 대조, 선택 망설임, 결과 인지 여부를 확인한다.
- 초기 관찰 세션은 대상 플레이어 5명 이상으로 시작한다. 최소 4명이 두 번째 호출까지 독립 자료 두 개를 열어 보고, 최소 4명이 한 선택의 화면·기록 변화를 설명하며, 마지막 회고에서 침묵이 맞는 네 번째 호출과 틀린 세 번째 호출의 이유를 구분하는지 기록한다. 미달 항목은 단서 배치나 문구를 수정한 뒤 다시 확인한다.
- 첫 플레이 결말 분포도 기록한다. 한 결말로 쏠리면 플레이어가 놓친 근거와 잔향 증가량을 먼저 확인하고 임계값을 조정한다.
- 완료 기준: 콘텐츠 담당자가 게임 로직 파일을 편집하지 않고 새 근무를 구성한다.

## 콘텐츠 완료 체크

- 모든 ID가 고유하고 팩 manifest에 연결되어 있다.
- 각 호출은 자료 참조, 선택지, 결과 문구, 판정 기준을 갖는다.
- 모든 자료/대사/결말 키가 선택한 언어에 존재한다.
- 모든 효과와 장면 상태가 스키마의 허용 목록에 있다.
- 모든 결정적 자료가 응답 전에 접근 가능하고 출처·시각이 보인다.
- 선택 뒤에 기대한 반응이 읽을 수 있는 텍스트와 화면/기록 상태로 나타난다. 음향만으로 전달하지 않는다.
- 선택 이력이 근무 로그에 정확히 남는다.
- 근무 전체의 모든 점수/잔향 조합에서 결말이 하나로 결정된다.
- 키보드 포커스와 Enter가 선택지·자료 탭·다음 호출 버튼의 기본 조작을 방해하지 않는다.

## 후속 제품 결정

- 콘텐츠 작성용 JSON 검증기를 별도 개발할지, 테스트 페이지로 충분한지
- 정적 파일 직접 열기와 로컬 개발 서버 중 어떤 배포/작업 흐름을 기준으로 둘지
- 후속 에피소드의 주된 변주가 새 장소인지, 새 증거 규칙인지, 기존 규칙의 조합인지
- 외부 제작자 팩을 받을 경우 신뢰 가능한 데이터 로더와 배포 검증을 어떻게 설계할지
